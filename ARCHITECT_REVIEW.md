# Architectural Review & Optimization Roadmap: Park Conscious

## 1. System Overview
The project is a monorepo using npm workspaces, bridging legacy static content with modern React apps and a serverless-ready backend.

- **Frontend:** React, Tailwind CSS, Vanilla HTML/JS.
- **Backend:** Node.js (Vercel Serverless Handlers) with Express wrapper.
- **Persistence:** MongoDB (Mongoose) with dual-database strategy.

## 2. Identified Bottlenecks
- **Monolithic Handlers:** `api/admin.js` is too large (~43KB), causing slow parsing and high cold starts.
- **Synchronous Operations:** Background tasks (email, media) block the request-cycle.
- **Database Indexing:** Missing compound indexes for common query patterns (status, date, organizerId).
- **Build Fragility:** Manual build scripts in root `package.json`.

## 3. Optimization Strategy (Phase 1)

### A. MongoDB Indexing
- **Event Schema:** Add indexes for `status`, `date`, `organizerId`, and `isPublic`.
- **Booking Schema:** Add compound indexes for `eventId + status` and `userId + status`.
- **Owner Schema:** Index `email` and `role`.

### B. Admin Handler Refactoring
- **Goal:** Reduce `api/admin.js` size by splitting it into functional modules.
- **Target Modules:**
    - `api/admin/events.js`: Event management logic.
    - `api/admin/users.js`: User and Organizer management.
    - `api/admin/bookings.js`: Transaction and booking oversight.
    - `api/admin/stats.js`: Dashboard and reporting logic.

## 4. Future Roadmap
- **Phase 2:** Implement Redis caching for high-traffic public routes.
- **Phase 3:** Migrate build system to Turborepo.
- **Phase 4:** Introduce background workers (BullMQ/Inngest) for email/media tasks.
